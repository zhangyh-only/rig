# 语言模板：TypeScript / JavaScript

适合：前端应用、Node 服务、组件库、脚本工具。

## 命名与结构
- [A桶] 文件名、组件名、hook/function 命名跟随项目现有约定。
- [B桶] UI 组件、业务状态、接口请求、工具函数分层清晰，不把所有逻辑塞进页面组件。
- [B桶] 公共类型放在项目约定位置；局部类型就近定义。
- [B桶] 不绕过已有请求封装、状态管理、权限和错误处理链路。

## 类型与错误处理
- [A桶] 新代码默认启用类型检查，不用 `any` 绕过问题；确需使用时写明原因。
- [B桶] 外部接口数据要有边界校验或明确的适配层。
- [B桶] 用户可见错误、空状态、加载态、权限态要按现有产品体验处理。

## 检查器建议
- [A桶] ESLint：语法、import、React hooks、未使用变量、危险写法。
- [A桶] Prettier 或项目格式化工具：格式统一。
- [A桶] `tsc --noEmit` 或框架 typecheck：类型正确性。
- [A桶] Vitest/Jest/Playwright：逻辑、组件、关键流程。

## 验证建议
- 组件/页面改动：lint + typecheck + 聚焦测试。
- 视觉或交互改动：本地启动后截图或浏览器验证。
- 接口 contract 改动：同步 mock、类型、调用方和验收用例。
