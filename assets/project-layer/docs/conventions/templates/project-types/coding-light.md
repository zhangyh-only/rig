# 项目类型模板：coding-light

适合：一次性脚本、内部小工具、demo、AI 技术预研、可丢弃实验代码。

## 应启用的规范层
- [B桶] `AGENTS.md` 写清脚本用途、入口命令、输入输出和风险边界。
- [B桶] `docs/conventions/` 保留最小规则：命名、目录、配置、日志、不可碰的资源。
- [A桶] `scripts/verify-local.sh` 至少能跑语法检查、单元测试或一次 dry-run。
- [C桶] 重要经验可写 `docs/lessons.md`；只有反复出现的问题才晋升为硬规范。

## 默认工程规则
- [B桶] 优先单入口、少抽象、少框架；不要为一次性需求搭大架子。
- [B桶] 外部输入、文件路径、远端地址、密钥和生产数据必须显式隔离。
- [B桶] 运行结果要可复现：命令、参数、样例输入输出写清楚。
- [A桶] 能加 dry-run 的脚本默认加 dry-run；不能 dry-run 时在文档中说明风险。

## 不该强上的内容
- 不强制完整 OpenSpec、复杂架构测试或多层审批。
- 不为尚未稳定的实验代码沉淀过细的领域规范。
