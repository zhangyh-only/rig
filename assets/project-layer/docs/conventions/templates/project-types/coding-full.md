# 项目类型模板：coding-full

适合：线上业务系统、正常研发项目、框架升级、多模块协作项目。

## 应启用的规范层
- [B桶] `AGENTS.md` 必须写清项目地图、构建命令、测试命令、本地启动或验证命令。
- [B桶] `docs/conventions/` 必须包含编码约定、结构约定和必要的领域约定。
- [A桶] `scripts/lint-one.sh` 应覆盖主要语言的单文件检查，未配置检查器时要明确跳过，不误拦。
- [A桶] `scripts/verify-local.sh` 应尽量串起编译、单测、轻量集成或冒烟验证。
- [C桶] 跨域、难回退、长期影响的技术选择写入 `docs/adr/`。

## 默认工程规则
- [B桶] 改动必须贴近现有分层、命名和错误处理方式，不顺手重构无关模块。
- [B桶] 变更接口、数据流、行为契约或验收口径时，应升级为 OpenSpec Change 或等价需求合同。
- [B桶] 多模块改动先确认调用链和影响范围，再改代码。
- [A桶] 新增或修改公共入口、接口、核心服务时，必须有对应测试或可执行验证。

## 收尾口径
- 说明本次改了什么、跑了什么验证、哪些需要真实环境联调。
- 如果验证受外部依赖阻断，要明确区分“代码未验证”与“基础设施不可达”。
- 对已接入 `rig` 的项目，优先通过重新运行 `/rig:init` 或 `rig doctor` 补齐缺口，不要求手工复制模板。
