# 项目类型模板：non-coding

适合：文档仓库、知识库、报告材料、面试资料、课程资料、运营说明。

## 应启用的规范层
- [B桶] `AGENTS.md` 写清资料范围、目录含义、输出格式和事实来源要求。
- [B桶] `docs/conventions/` 重点写资料处理规则，不写无关代码规范。
- [A桶] 如有 Markdown，可按需接 markdownlint、链接检查或文件命名检查。
- [C桶] 关键口径变化要保留原因，必要时写 ADR 或决策记录。

## 默认资料规则
- [B桶] 不确定的事实必须标注“待确认”，不要补脑编造。
- [B桶] 更新已有知识库时，优先保留原结构和原骨架做增量补写。
- [B桶] 摘要、评估、报告要区分原文事实、推断和主观判断。
- [B桶] 输出给业务方的材料先讲价值、机制链路和可执行抓手，再讲技术细节。
- [A桶] 文件命名、日期目录、版本号如项目已有规则，应做成脚本检查。

## 验证方式
- 核对输入资料是否全部读取。
- 核对产物格式是否符合模板。
- 核对引用、数据、日期、姓名、版本号等高风险事实。
- 无法验证的内容要列入风险或待确认。
